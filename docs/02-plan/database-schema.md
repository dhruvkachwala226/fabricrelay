# MongoDB schema

Five product collections and one operational collection use Mongoose strict schemas. Object references below are ObjectIds. All root records have a required generated ObjectId `_id` and UTC `createdAt` and `updatedAt` unless stated otherwise. Embedded records inherit parent scope. A `?` marks an optional field. Optional fields are absent unless a default is documented. Update DTOs never control ownership, timestamps, audit fields or normalization keys.

| Entity and storage | Fields, types and defaults | Validation, relationships and lifecycle |
| --- | --- | --- |
| User in `users` | `email`, `emailKey` strings, `role` enum, `businessId?` ObjectId, `status` enum default INVITED, `sessionVersion` integer default 0, `passwordHash?` string, `activationTokenDigest?` string, `activationExpiresAt?` Date, `activatedAt?`, `suspendedAt?`, `archivedAt?` Dates | Normalize email into a globally unique key. WHOLESALER_ADMIN requires one business and SUPER_ADMIN has platform scope. Active users require password hashes. INVITED, ACTIVE, SUSPENDED and archived-by-timestamp describe account access. Expired activation is denied at read time. Rotate or clear tokens on use or reissue. Keep archived identity for audit references and remove credentials. |
| Business in `businesses` | `displayName`, `slug` strings, `description?` string, `logo?` MediaRef, `status` enum default INACTIVE, `catalog` embedded default DRAFT, `visibilityVersion` integer default 0, `archivedAt?` Date | Business ID is the tenant root. INACTIVE, ACTIVE and SUSPENDED. Reserve globally unique lowercase slugs even when archived. Archive by an explicit operator procedure after access is disabled. Preserve audit and inquiry links. |
| Catalog embedded in Business | `state` enum default DRAFT, `firstPublishedAt?`, `publishedAt?`, `unpublishedAt?`, `archivedAt?` Dates | One per business, identified by parent ID. Published content derives from currently eligible listings. Parent timestamps reflect changes. Archive is terminal. No independent collection or catalog ID. |
| Fabric in `fabrics` | `businessId` ObjectId, `slug` string, `state` enum default DRAFT, `quality?`, `designCode?`, `designCodeKey?`, `qualityKey?`, `description?` strings, `widthInches?`, `gsm?` Decimal128, `moq?` MOQ, `priceVisibility` enum default QUOTE_ONLY, `ratePaisePerMeter?` safe integer, `photos` MediaRef[] default empty, `colorways` Colorway[] default empty, `version` integer default 0, `firstPublishedAt?`, `publishedAt?`, `archivedAt?` Dates | Draft may be partial. Publish requires quality, design code, width, GSM, MOQ, at least one verified swatch photo and one listed named color. PUBLISHED listing edits must preserve readiness. Unique normalized design code and slug per tenant, including archived records. Archive unlists the fabric and reserves identifiers. |
| Colorway embedded in Fabric | `_id` ObjectId, `name`, `nameKey` strings, `availability` enum default UNAVAILABLE, `photo?` MediaRef, `createdAt`, `updatedAt`, `archivedAt?` Dates | AVAILABLE or UNAVAILABLE is manually maintained. Enforce normalized name uniqueness among listed colors in a guarded parent write. Remove from listings by archiving or pruning embedded records after media detachment. Inquiry snapshots preserve old names and states. Bound to 24 listed colors and purge archived entries as needed to keep total bounded. |
| Inquiry in `inquiries` | `businessId`, `fabricId`, `colorwayId` ObjectIds, `reference`, `requestKey`, `payloadDigest` strings, `type` enum, `status` enum default NEW, `buyerName` string, `contact` tagged email or phone, `note?` string, `requestedMeters?` Decimal128, `belowMoq` boolean default false, `snapshot` object, `statusChangedAt?` Date, `statusChangedBy?` ObjectId | References must match one tenant and embedded color. Quote requires positive meters. Sample omits quantity. Immutable snapshot stores quality, code, width, GSM, name, availability, MOQ, price visibility and public rate when visible. Contact fields are private and excluded from queue DTOs. Operator purge procedure deletes pilot inquiries after the retention decision. |
| AuditLog in `auditLogs` | `actorUserId` ObjectId, `businessId?` ObjectId, `action`, `targetType`, `targetId`, `requestId` strings, `metadata?` typed allowlisted object, `createdAt` Date | Append-only. Platform events may omit the business only when no tenant is involved. Record actor, tenant, action and time for provisioning and lifecycle changes. No passwords, buyer data, token material or raw diffs. Retain according to operator policy and purge only through an approved maintenance procedure. |

**MOQ** contains positive `quantity` (Decimal128), `unit` (METER, LUMP, or OTHER), `unitLabel?` for OTHER or a display alias, and `metersPerLump?` or `metersPerUnit?` (positive Decimal128, relevant units only). Conversions use exact fixed-scale arithmetic. METER uses its own quantity. Apply up to two fractional digits to inches and GSM, and up to three to meters and MOQ amounts. Serialize decimals as strings through REST. Proposed upper guards are 300 inches, 2,000 GSM and one million meters per request or equivalent MOQ. Design codes are trimmed, case-folded and limited to 40 characters. Name keys are normalized consistently. Rate visibility is INDICATIVE or QUOTE_ONLY. INDICATIVE requires a positive safe integer paise value. No floating-point pricing. Smoke fixture is MS-402, 58 inches, 80 GSM, 7,400 paise per meter and 1 lump of 100 meters.

**MediaRef** contains a server-generated opaque `mediaId` string, provider `assetId` and `publicId` strings, integer `version`, `bytes`, `width`, `height`, the `format` enum and optional author-supplied plain-text `alt`. Ownership comes from its parent plus the confirmed upload record. Limit swatch photos to eight. See [media lifecycle](image-upload-architecture.md).

**Operational records** use `operations` with discriminator `kind` enum, scoped `key` string, optional tenant `businessId`, and optional `expiresAt` Date. A counter has a bounded `acceptedAt` Date array or an auth-attempt window. A media record has a target type and optional fabric/colorway ObjectIds, an expected public ID, lease expiry, a state enum, verified media metadata when attached, and retry count plus next attempt time during cleanup. Keep one active asset record per media ID for scoped delivery lookup and require the attachment to still exist. Inquiry counters and media records always have a tenant. Platform login throttles can be global. A single-field TTL on `expiresAt` cleans eligible records asynchronously. Check lease expiry in application logic. Set a media record's TTL only after reconciliation or terminal deletion.

Business and Fabric each have an internal integer `intakeFence` defaulting to zero. Inquiry insertion increments both in the same transaction to serialize against concurrent eligible-state writes. Keep these fields separate from editor-facing versions and suppress timestamp changes for fence-only updates. Business lifecycle and catalog writes update the business document. Fabric and colorway lifecycle writes update the same fabric document as the fence.

## Indexes and access patterns

| Collection | Index and reason |
| --- | --- |
| users | Unique `emailKey` for sign-in and provisioning. `(businessId, status, _id)` for assigned admins. Unique partial `activationTokenDigest` when present for single-use redemption. |
| businesses | Unique `slug` for public resolve and reservation. `(status, createdAt DESC, _id DESC)` for platform operations. `(catalog.state, createdAt DESC, _id DESC)` for platform catalog inspection. |
| fabrics | Unique `(businessId, slug)` and partial unique `(businessId, designCodeKey)` when the key exists. `(businessId, state, updatedAt DESC, _id DESC)` for listing and paging. `(businessId, state, _id)` for stable public browsing. Add dedicated prefix indexes only after measuring the bounded tenant search with `explain`. |
| inquiries | Unique `(businessId, requestKey)` and `(businessId, reference)`. `(businessId, createdAt DESC, _id DESC)` for queue. Add `(businessId, type, status, createdAt DESC, _id DESC)` if both optional filters warrant it. |
| auditLogs | `(createdAt DESC, _id DESC)` for recent platform activity and `(businessId, createdAt DESC, _id DESC)` for the explicit platform tenant filter. |
| operations | Unique `(kind, key)` and single-field TTL `expiresAt`. `(kind, state, nextAttemptAt, _id)` for resumable media reconciliation and `(businessId, kind, state)` for tenant media quotas. |

Use owner plus ID predicates on scoped detail reads and mutations. Indexes reflect access patterns and do not grant authorization. Public search uses normalized escaped prefixes for quality and design code and an embedded element match so color and availability refer to the same colorway. Return only the requested page with a stable tie-breaker. Check representative query plans against a 100-fabric fixture before adding multikey or extra optional-filter indexes. Deploy indexes explicitly and check uniqueness before enabling writes. See the [ER diagram](entity-relationship.md) and [inquiry transaction](inquiry-workflow.md). [MongoDB TTL behavior](https://www.mongodb.com/docs/manual/core/index-ttl/)
