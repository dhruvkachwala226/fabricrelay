# Cloudinary media lifecycle

Use direct signed upload for file bytes. A wholesaler must have an active tenant and an authorized existing draft, colorway or business target. Anonymous uploads and unsigned presets are outside this workflow. Keep the Cloudinary API secret server-only. The browser receives the provider URL, API key, timestamp, signature and exact permitted fields.

1. The mobile UI checks JPEG, PNG or WebP and the 5,000,000-byte limit before upload. The server verifies the declared metadata, target ownership, available slots and persistent signing quota. Use one file per lease, a random server-owned ID, authenticated delivery type, an image-only signed preset and overwrite disabled. Include ownership and lease context in signed parameters.
2. Cloudinary admits the upload. Enforce format, size and pixel limits at the provider where supported. Treat client metadata as advisory. Before enabling production, verify provider rejection or authenticated quarantine and deletion of unsupported or oversize bytes with real boundary fixtures. A modified target, type or resource URL can never make a file attachable.
3. Confirmation loads the still-valid lease and asks Cloudinary for the actual immutable asset ID, scoped public ID, type, format, dimensions and byte count. Reject mismatch, unsafe dimensions and expired or cross-tenant leases. In a transaction, atomically attach the verified reference to its scoped parent, bump its version as applicable and close the lease. A repeat confirmation returns the attached reference while still owned. Default to a 10-minute app lease. Provider acceptance can last longer than the application lease, so reconciliation observes the provider validity window.
4. Fabric galleries support up to eight swatch photos. Each colorway and the business profile support one image. Store alt text with the attachment. For a replacement, upload and verify the new asset, swap references atomically and queue cleanup for the old asset. A failed replacement leaves the old image working.

## Delivery and cleanup

Keep originals and derivatives authenticated. The app media endpoint verifies a live private owner or public business/catalog/listing gate. It streams an allowlisted transformed variant from Cloudinary and never redirects to a reusable signed provider URL. Cap variant sizes well below the Vercel response limit. Use versioned width variants (e.g. 160, 480 and 960 px), responsive srcset, automatic format and quality, lazy loading beyond the first viewport and metadata stripping. Send no-store on the application response and measure repeated publishes and public mobile performance. Use Cloudinary caching for its upstream transforms. A revoked listing blocks future app delivery. Downloaded bytes remain with the recipient.

Deletion first detaches a scoped reference and durably queues the server-owned asset ID in the same transaction. Reject deletion that breaks publication readiness. Cleanup rechecks expected ownership, provider metadata, removal state and absence of active references before deletion. Ignore provider already missing responses and retry transient failures with capped backoff. Upload leases that expire remain discoverable until after provider signature expiry and a grace period. Reconcile unattached assets and late uploads before expiring the operational record. Run an operator job during the pilot, then automate in M13 if the chosen hosting plan supports the cadence. Alert on repeated failures. Retry individual mobile photos, retain usable draft fields and show size/type/provider errors next to the failed file.

Direct upload avoids the standard 4.5 MB Vercel function payload cap. Confirm provider-side settings and app delivery on an isolated environment before production.
